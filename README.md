# GraphQL-Markdown + Nuxt demo

[![Open with CodeSandbox](https://assets.codesandbox.io/github/button-edit-lime.svg)](https://codesandbox.io/p/sandbox/github/graphql-markdown/demo-nuxt/tree/main)

Unlike the other demos, this one does not sit on a documentation theme. It generates the Markdown with [GraphQL-Markdown](https://graphql-markdown.dev/), reads it back through [Nuxt Content](https://content.nuxt.com/), and renders a two-column API reference built from [Nuxt UI](https://ui.nuxt.com/) components — prose on the left, the schema definition and the examples on the right.

## 🚀 Project Structure

Inside your GraphQL-Markdown + [Nuxt](https://nuxt.com/) project, you'll see the following folders and files:

```
.
├── app/
│   ├── assets/
│   │   └── css/main.css
│   ├── components/
│   │   ├── SchemaCodeCard.vue
│   │   ├── SiteFooter.vue
│   │   └── SiteHeader.vue
│   ├── composables/
│   │   └── useApiNavigation.ts
│   ├── pages/
│   │   ├── api-reference/
│   │   │   └── [...slug].vue
│   │   └── index.vue
│   ├── utils/
│   │   ├── api-document.ts
│   │   └── mdc.ts
│   ├── app.config.ts
│   └── app.vue
├── content/
│   └── api-reference/          # generated by GraphQL-Markdown
├── public/
├── schema/
│   └── api.graphql
├── content.config.ts
├── generate-docs.ts
├── graphql-markdown-formatter.ts
├── nuxt.config.ts
├── package.json
└── tsconfig.json
```

There is no `gqlmd` CLI step and no `.graphqlrc`. `generate-docs.ts` calls `runGraphQLMarkdown` directly, and `nuxt.config.ts` runs it from the `build:before` hook — so `npm run dev` and `npm run build` regenerate `content/api-reference` on their own. The config also watches `schema/api.graphql` and both scripts, so editing the schema restarts the dev server against fresh documentation.

`graphql-markdown-formatter.ts` is a small formatter add-on. It emits `.md` rather than `.mdx`, because Nuxt Content's search indexer (`queryCollectionSearchSections`) only reads Markdown; renders type badges as `<mark class="gqlmd-mdx-badge-*">`; and turns deprecation admonitions into a plain `<aside>`. The reference page promotes both into Nuxt UI components — `UBadge` and `UAlert` — while parsing the page.

`app/pages/api-reference/[...slug].vue` is that page. It queries the generated Markdown as a Nuxt Content AST and rewrites it before rendering: `app/utils/mdc.ts` holds the AST primitives, `app/utils/api-document.ts` the schema-aware queries and transforms, and `useApiNavigation` derives a navigation tree from the content paths, which the sidebar and the `⌘K` search palette both read. The GraphQL definition and the examples are lifted out of the prose into `SchemaCodeCard`s, highlighted with [Shiki](https://shiki.style/); on operation pages the request and its response are shown as a [code group](https://ui.nuxt.com/docs/typography/code-group).

`schema/api.graphql` is a small workspace API that exercises the interesting cases: `@example` and `@exampleResponse` on every operation, `@deprecatedType` on a superseded object, field-level `@deprecated`, a union, an interface, and a paginated connection. `@exampleResponse` is a custom section registered in `generate-docs.ts`, not a built-in.

## 🧞 Commands

All commands are run from the root of the project, from a terminal:

| Command            | Action                                                                       |
| :----------------- | :--------------------------------------------------------------------------- |
| `npm install`      | Installs dependencies                                                        |
| `npm run dev`      | Generates the documentation, then serves it on `localhost:3000`              |
| `npm run build`    | Generates the documentation and builds the server bundle to `./.output`      |
| `npm run generate` | Generates the documentation and builds the static site to `./.output/public` |
| `npm run preview`  | Serves the production build locally                                          |

## 🏎️ Quick start

Get your demo up and running with these commands:

```bash
npm install
npm run dev
```

> 🧑‍🚀 **Edit `schema/api.graphql` to try with your own GraphQL schema.** The GraphQL-Markdown options live in `generate-docs.ts`.
