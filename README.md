# GraphQL-Markdown + Nuxt demo

[![Open with CodeSandbox](https://assets.codesandbox.io/github/button-edit-lime.svg)](https://codesandbox.io/p/sandbox/github/graphql-markdown/demo-nuxt/tree/main)

Live demo: [graphql-markdown.dev/demo-nuxt](https://graphql-markdown.dev/demo-nuxt)

A richly customized example of a GraphQL API reference site built on [GraphQL-Markdown](https://graphql-markdown.dev/) + [Nuxt Content](https://content.nuxt.com/) + [Nuxt UI](https://ui.nuxt.com/), consuming the `@graphql-markdown/nuxt-theme` reusable Nuxt layer. The layer provides the two-column API reference UI (prose on the left, schema definitions and examples on the right); this project extends it with decorators: an "Example Variables" section (`@exampleVariables`), an "Example Response" section (`@exampleResponse`), and a type-level deprecation badge and callout (`@deprecatedType`). A custom formatter also links the types named in deprecation reasons to their sections.

## 🚀 Project Structure

This project extends `@graphql-markdown/nuxt-theme`, which provides:
- The two-column API reference layout and theme
- Components: `SiteHeader`, `SiteFooter`, `SchemaCodeCard`
- Page and layout templates
- Content navigation composables
- CSS custom property theming tokens

This project itself contributes:

```
.
├── app/
│   ├── app.vue                 # demo-specific landing page wrapper
│   ├── layouts/
│   │   └── default.vue         # demo-specific layout
│   └── pages/
│       └── index.vue           # demo-specific landing page
├── content/
│   └── api-reference/          # generated by GraphQL-Markdown
├── schema/
│   └── homepage.md             # reference intro (title, SEO description, body)
├── content.config.ts           # required per-project: content collection config
├── custom-mdx.mjs              # theme formatter extended to link types in deprecation reasons and to their Markdown copies
├── generate-docs.ts            # custom entry point: homepage, formatter, shared reference options
├── graphql.config.mjs          # `markdown` project for the Markdown copies
├── lib/
│   ├── markdown-copy.mjs       # plain Markdown formatter for the copies
│   └── reference-options.mjs   # schema, @exampleVariables, @exampleResponse, @deprecatedType shared by both outputs
├── nuxt.config.ts              # extends: ['@graphql-markdown/nuxt-theme']
├── package.json
└── tsconfig.json
```

`generate-docs.ts` exports a `generate()` function created by the layer's `createGenerateDocs` factory, configured with demo-specific options: the schema URL, the `schema/homepage.md` homepage (rendered as the reference's intro), custom `@exampleVariables` and `@exampleResponse` sections (not built-in), custom `@deprecatedType` decorators, and the `custom-mdx.mjs` formatter. The layer's `gqlmd-generate` Nuxt module invokes this function during the `modules` lifecycle, before Nuxt Content indexes the directory — fixing the cold-build bug that would silently 404 the reference on first clone.

### Linked deprecation reasons

`custom-mdx.mjs` follows the [Link entities in deprecation reasons](https://graphql-markdown.dev/docs/customize/hooks#link-entities-in-deprecation-reasons) recipe. It extends the theme formatter (`@graphql-markdown/nuxt-theme/formatter`) so that a schema type written as inline code in a deprecation reason links to its section. For example, `ProjectStatus` in the `Project.state` notice links to the `ProjectStatus` enum. The `@deprecatedType` notices are linked too.

`generate-docs.ts` loads it with the `formatter` option of `createGenerateDocs`, as a URL relative to the file:

```ts
formatter: new URL("./custom-mdx.mjs", import.meta.url).href,
```

The formatter imports `toLink` from `@graphql-markdown/printer-legacy`, so the demo declares that package as a dependency.

### Markdown copies

Each type is also published as plain Markdown at `/api-reference/<slug>.md`, and its section links to it with "View as Markdown". It follows the [Markdown copies](https://graphql-markdown.dev/docs/guides/markdown-copies) guide:

- `graphql.config.mjs` defines a `markdown` project that renders the schema with the plain Markdown formatter into `.markdown-copies/`.
- `lib/markdown-copy.mjs` is that formatter, based on the mdBook preset.
- `lib/reference-options.mjs` holds the schema, loaders, print options and decorators shared by `generate-docs.ts` and the `markdown` project, so both outputs have the same content.
- `custom-mdx.mjs` has the `afterRenderTypeEntitiesHook` that appends the "View as Markdown" link to each page.
- The `copies` script generates the copies and copies `.markdown-copies/` into `public/` before the Nuxt build, because Nuxt only serves `public/` as-is.

The schema is the [GraphQL-Markdown demo schema](https://raw.githubusercontent.com/graphql-markdown/graphql-markdown/main/tests/e2e/__data__/demo_schema.graphql), shared by all GraphQL-Markdown demos: a small workspace API that exercises the interesting cases: `@example`, `@exampleVariables`, and `@exampleResponse` on every operation, `@deprecatedType` on a superseded object, field-level `@deprecated`, a union, an interface, and a paginated connection.

## 🧞 Commands

All commands are run from the root of the project, from a terminal:

| Command             | Action                                                                                                      |
| :------------------ | :---------------------------------------------------------------------------------------------------------- |
| `pnpm install`      | Installs dependencies                                                                                       |
| `pnpm run dev`      | Regenerates the documentation if needed, then serves it on `localhost:3000`                                 |
| `pnpm run build`    | Regenerates the documentation if needed and builds the server bundle to `./.output`                         |
| `pnpm run generate` | Regenerates the documentation and builds the static site to `./.output/public` (verifies cold-build works)  |
| `pnpm run copies`   | Renders the Markdown copies into `./.markdown-copies` and copies them into `./public` (run by `dev`, `build` and `generate`) |
| `pnpm run preview`  | Serves the production build locally                                                                         |

Documentation is regenerated automatically when `generate-docs.ts` changes.

### Theme source

`@graphql-markdown/nuxt-theme` and the other `@graphql-markdown/*` packages come from the npm registry. pnpm holds back releases younger than its minimum release age. `minimumReleaseAgeExclude` in `pnpm-workspace.yaml` lists the exact GraphQL-Markdown versions the demo adopts as soon as they're published. Add the new versions there when bumping.

### Testing an unreleased graphql-markdown change

Every same-repository pull request on the [graphql-markdown monorepo](https://github.com/graphql-markdown/graphql-markdown) publishes its packages to [pkg.pr.new](https://pkg.pr.new). To run this demo against one:

- **In CI:** Actions → **graphql-markdown PR preview** → Run workflow with the PR number. It installs the previews, checks that every `@graphql-markdown/*` package resolved to them, builds the site and runs the visual tests. Screenshots are kept as a workflow artifact; nothing is uploaded to Argos, since the run executes code from the PR.
- **Locally:** add an `overrides:` entry in `pnpm-workspace.yaml` for each `@graphql-markdown/*` package, then run `pnpm install --no-frozen-lockfile`. Don't commit the change.

  ```yaml
  overrides:
    "@graphql-markdown/core": https://pkg.pr.new/graphql-markdown/graphql-markdown/@graphql-markdown/core@<pr-number>
  ```

## 🏎️ Quick start

Get your demo up and running with these commands:

```bash
pnpm install
pnpm run dev
```

> 🧑‍🚀 **Point `schema` in `generate-docs.ts` at your own GraphQL schema to try it.** The GraphQL-Markdown options (schema, loaders, homepage, hierarchy, decorators, formatter) live in `generate-docs.ts`.

## 🚢 Deployment

The `Deploy to GitHub Pages` workflow generates the documentation, builds the static site and publishes `./.output/public` to the `gh-pages` branch. It is run manually from the Actions tab, and sets `NUXT_APP_BASE_URL=/demo-nuxt/` so assets and links resolve under the Pages subpath — leave it unset to build for the root.
